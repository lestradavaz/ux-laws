# Zeigarnik Effect

## Principle and evidence

Unfinished or interrupted work can remain mentally salient. Help users understand, resume, finish, or deliberately abandon outstanding tasks.

The catalog summarizes a historic effect concerning unfinished-task recall. Its strength and relevance vary with conditions. It is not a promise that incomplete onboarding will drive engagement or that artificial progress improves user outcomes.

## Observable triggers

- Users lose their place after an interrupted process.
- The product shows many unexplained incomplete badges.
- Reminders or checklists pressure users to perform optional tasks.

## Implementation actions

1. Represent outstanding work accurately with status, last completed step, and a specific next action. Distinguish a user-owned unfinished task from a product-promoted suggestion.
2. Preserve drafts and relevant context where feasible. Give users a visible resume route and tell them whether work is saved, pending, expired, or requires revalidation.
3. Allow tasks to be dismissed, deferred, or abandoned when the domain permits. Explain consequences for genuinely required work instead of using guilt or indefinite warning badges.
4. Use reminders only with an appropriate purpose and user control. Respect timing, consent, notification settings, and the task's actual urgency.
5. Provide closure on completion or cancellation. Remove stale incomplete indicators and clarify whether deletion or abandonment actually occurred; do not invent progress or manufacture unfinished loops.

## Example

A saved application displays Draft saved, identifies the last edited section, and offers Resume or Discard draft. Optional profile tasks remain separate. When the user resumes, changed requirements are explained without silently resetting earlier valid answers. Completion removes the draft reminder and provides the confirmed result.

## Counterexample

A product marks optional marketing preferences as incomplete account setup and repeatedly displays a nearly full progress ring. Users cannot dismiss the ring or know whether their core account already works.

## Limits and conflicts

Mental salience can become anxiety or coercion. The user's decision to stop is a valid outcome, and some tasks should expire for real security or process reasons. Preserve context without retaining sensitive data longer than appropriate. Motivation is secondary to clarity, control, and meaningful completion; evaluate resumption and task outcome instead of engagement alone.

## Acceptance checks

- Unfinished status names actual user work and a clear next action.
- Users can resume with accurate preserved context or understand why it expired.
- Optional tasks and reminders are controllable and distinguishable from prerequisites.
- Completed, canceled, and discarded tasks no longer carry misleading incomplete indicators.
