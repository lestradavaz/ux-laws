# Paradox of the Active User

## Principle and evidence

People often start acting before studying documentation because their immediate goal is to get work done. Place useful learning and recovery where the work happens.

This is a behavior-oriented usability concept, not a literal claim that nobody reads manuals. The catalog relates immediate action to missed opportunities for learning more efficient methods. Design for both exploratory use and deliberate reference.

## Observable triggers

- A product requires a long tutorial before the first useful task.
- Users repeatedly make the same recoverable error despite extensive documentation.
- Advanced features exist but are discoverable only through a manual.

## Implementation actions

1. Identify the first meaningful user outcome and provide a safe route to it. Ask only for prerequisites required by that outcome; make optional learning available separately.
2. Place specific instructions near unfamiliar or consequential controls. Explain format, scope, and result before errors occur instead of offering a generic help link alone.
3. Use real task examples, reversible exploration, and contextual guidance. Tooltips supplement labels; essential instructions must remain reachable on touch, keyboard, and assistive paths.
4. Provide searchable reference and discoverable efficiency tools. Introduce shortcuts or batch operations at a moment when their benefit is relevant, without repeatedly interrupting learned use.
5. Remember dismissed guidance when appropriate, allow it to be reopened, and support recovery. Observe whether people succeed without prior training, while retaining deeper documentation for expert needs.

## Example

A first-time editor can create a draft from an empty-state action with a brief explanation. The inspector gives inline hints for unfamiliar properties. Export explains destination and format when needed. A shortcut panel is optional and searchable; it does not block editing or become the only way to learn essential controls.

## Counterexample

A mandatory walkthrough points to every control before the user has a task. Once dismissed, instructions cannot be recovered, and errors merely say to consult the manual.

## Limits and conflicts

Some domains require training, consent, or competence checks. Contextual guidance cannot replace those requirements. Experts may actively prefer reference documentation and fast, unobstructed controls. Treat skipping help as evidence about relevance and timing, not proof that users are careless. Guidance must not obscure current state or increase interruption during critical work.

## Acceptance checks

- A new user can achieve the intended first outcome through safe exploration.
- Essential guidance is accessible through relevant input modes and can be revisited.
- Errors explain a practical correction near the affected work.
- Experienced users can discover efficiencies without repeating beginner interruptions.
