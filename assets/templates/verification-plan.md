# UX verification plan

Use when a persistent plan is requested. Tests should target user outcomes and meaningful failure modes.

## Change and environment

Record affected journey, starting state, outcome, platforms/modalities, relevant access needs, and tools available.

## Cases

| Case | Starting condition and action | Observable expected result | Method | Evidence/status |
| --- | --- | --- | --- | --- |

Populate with applicable normal, boundary, failure, recovery, and modality cases. A proposed expected result is not an observed result.

## Measurement

Define metrics, baseline, collection method, and decision threshold only when justified. Include guardrails for errors, access barriers, privacy, and recovery. Record sample limitations for user evaluation.

## Completion and limits

List passed, failed, unavailable, and deferred checks. Explain remaining uncertainty and the next action needed. Do not infer accessibility conformance or user validation from partial coverage.
